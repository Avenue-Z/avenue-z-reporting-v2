# next 16.1.6 to 16.3.6 and next-auth beta.30 to beta.32: what I tried before upgrading

Three throwaway trials, run before the upgrade so the PR is built on what they showed, not on release notes.

## 1. Saves and the cache (the one that changed the code)

A two-page app with the same client Router Cache setting as this repo (`staleTimes.dynamic: 180`) and a
`db`-tagged `unstable_cache`, built and run with `next start` on each version. A Server Action wrote a value
and invalidated the tag.

| What the person does | 16.1.6, `revalidateTag('db', 'max')` | 16.3.6, same call | 16.3.6, `updateTag('db')` |
|---|---|---|---|
| Save, then `router.refresh()` | new value | **old value** (seen twice) | new value |
| Save, no refresh | old value | old value | new value |
| Leave and come back within 180 s | old value | old value | new value |

On 16.1.6 the action re-rendered the page itself, which started the background refresh of the stale entry,
so the `router.refresh()` after it read fresh data. From 16.2 (vercel/next.js#88069) the action no longer
re-renders, so that refresh is the first read after the write and gets the stale entry. `updateTag` expires
the tag at once and behaved the same on both versions, so every save now uses it
(`app/actions/cache-invalidation.test.ts` pins all 18 calls).

## 2. Sessions across the upgrade

A session cookie encoded by `@auth/core` 0.41.0 decodes under 0.41.3 and the reverse, with both cookie names
as the salt, every claim intact; a wrong secret is rejected. Nobody is signed out by the upgrade or by a
rollback. `lib/auth/service-cookie.test.ts` guards the internal cookie the cache warmer and sweeps mint.

## 3. The built-in screens

Read from both npm packages. The default 404 (`builtin/not-found.js`, `http-access-fallback/error-fallback.js`)
is byte-identical. The default crash screen (`builtin/global-error.js`) and the static 500 page
(`builtin/app-error.js`) were redesigned in 16.2. `app/global-error.tsx` keeps the crash screen that app errors
reach exactly as 16.1.6 drew it. Two framework-level fallbacks keep Next's built-in pages whatever the app
provides, so they show the new design: the static 500.html, and the router's last-resort boundary for when the
framework itself fails (`client/components/app-router.js`, `AppRouter`, in both versions).

## Checked on the upgraded tree
The route list and each route's static or dynamic marker are identical to 16.1.6's build, and the compiled
CSS is the same 1179 rules once minifier whitespace is ignored.
